## What I do

Repair precision failures in AscendC kernels generated by AscendOpGenAgent.

When AscendOpGenAgent's Phase 4 verification reports a precision mismatch
(mismatch_ratio > 0, not shape mismatch or NaN/Inf), this skill:
1. Runs detailed numerical forensics (Python script)
2. Agent analyzes forensics + kernel code + model.py reference logic
3. Agent fixes the kernel C++ code
4. Rebuilds and re-verifies
5. Gate-controlled loop decides continue or stop

## When to use me

Called automatically from ascend-kernel-developer Phase 4 when verification
fails with a precision mismatch after compilation succeeds.

## Prerequisites

- `{workdir}/{task}/model.py` — reference PyTorch implementation
- `{workdir}/{task}/model_new_ascendc.py` — AscendC wrapper
- `{workdir}/{task}/kernel/*.cpp` — AscendC kernel sources
- Build environment: `utils/build_ascendc.py` and `utils/verification_ascendc.py` available

## Argument

```
task_name=<task> workdir=<workdir> soc_version=<soc>
```

- `task_name`: task directory name under workdir
- `workdir`: path to AscendOpGenAgent root (default: current directory)
- `soc_version`: SoC version for build_ascendc.py (default: Ascend910B2)

## Workflow

**All thinking, analysis, reasoning must use Chinese.**

**Core principle: Python scripts do deterministic work (forensics, Gate), Agent does reasoning work (analysis, fix).**

---

### Step 0: Initialize

Set round counter `attempt = 0`.

**0.1 Save immutable baseline snapshot (first execution only):**
```bash
if [ ! -d "{task_dir}/precision_tuning/history/baseline/code_snapshot" ]; then
    mkdir -p "{task_dir}/precision_tuning/history/baseline/code_snapshot"
    cp "{task_dir}/kernel/"*.cpp \
       "{task_dir}/precision_tuning/history/baseline/code_snapshot/"
    echo "Baseline snapshot saved"
fi
```

**0.2 Save current round starting snapshot:**
```bash
mkdir -p "{task_dir}/precision_tuning/history/attempt_0/code_snapshot"
cp "{task_dir}/kernel/"*.cpp \
   "{task_dir}/precision_tuning/history/attempt_0/code_snapshot/"
```

---

### Step 1: Precision Forensics

Run the forensics script to collect detailed diff data:

```bash
cd {workdir}
python3 skills/ascendc/ascendc-precision-tuner/scripts/precision_forensics.py \
    {task_name} --workdir "{workdir}" --attempt {attempt}
```

Then validate with Gate-F:
```bash
python3 skills/ascendc/ascendc-precision-tuner/scripts/precision_gate.py \
    --step forensics --task-name {task_name} --workdir "{workdir}" --attempt {attempt}
```

**Gate-F failure → STOP, check error output.**

---

### Step 2: Deep Analysis + Fix Plan (Agent reasoning)

**Read:** `{task_dir}/precision_tuning/forensics_report_{attempt}.json`

Write analysis to `{task_dir}/precision_tuning/precision_audit_{attempt}.md`.

**Required sections:**

```
[FORENSICS_SUMMARY]
  - primary_hint, primary_confidence, primary_evidence
  - mismatch_ratio, max_abs_diff, mean_abs_diff
  - error_distribution (sign_analysis.bias_direction)
  - worst_elements (top 3)
  - tail_analysis
  - dimension_analysis
  - L8_operator.op_type

[COMPUTATION_DECOMPOSITION]
  - Decompose model.py forward() into computation steps
  - For each step: operation name, input source, output shape, precision risk

[KERNEL_STEP_TRACE]
  - Trace kernel/*.cpp Compute() function
  - Map each kernel step to computation decomposition step
  - Mark match status with ✅/⚠️/❌

[ROOT_CAUSE]
  - Evidence chain linking numerical data to code issue
  - Confidence level

[FIX_PLAN]
  - Specific fix direction
  - Files to modify, line numbers or function names
  - Expected effect

[TARGET_FILES]
  - List of files to modify

[DIRECTION_ASSESSMENT]  (required when attempt > 0)
  - Previous round fix direction
  - Whether to continue same direction (是/否)
  - Reason
```

**Knowledge base search (optional but recommended):**
```bash
python3 skills/ascendc/ascendc-precision-tuner/scripts/precision_knowledge.py search \
    --kb-path skills/ascendc/ascendc-precision-tuner/references/precision_knowledge_base.json \
    --op-type <op_type> --pattern <primary_hint> --top-k 3
```

Validate with Gate-A:
```bash
python3 skills/ascendc/ascendc-precision-tuner/scripts/precision_gate.py \
    --step audit --task-name {task_name} --workdir "{workdir}" --attempt {attempt}
```

**Gate-A failure → complete missing sections, do not count as an attempt.**

---

### Step 3: Code Fix (Agent execution)

Apply fixes according to [FIX_PLAN]. Modify files in `{task_dir}/kernel/`.

**Rules:**
1. Follow FIX_PLAN strictly, do not expand scope
2. Write complete files, do not truncate
3. Use actual variable names from the code
4. Do NOT shrink shapes, add skips, enlarge tolerance, or delete functionality

Validate with Gate-X:
```bash
python3 skills/ascendc/ascendc-precision-tuner/scripts/precision_gate.py \
    --step fix --task-name {task_name} --workdir "{workdir}" --attempt {attempt}
```

**Gate-X failure → check files are saved correctly.**

---

### Step 4: Rebuild + Verify

**4.1 Build:**
```bash
cd {workdir}
python utils/build_ascendc.py {task_name} -v {soc_version} --clean
```

Build failure handling:
- Analyze compiler error, fix code (max 3 compile retries)
- After each failure, update `{task_dir}/precision_tuning/compilation_log_{attempt}.json`
- If 3 retries still fail → restore from code_snapshot, return to Step 2

**4.2 Verify:**
```bash
python utils/verification_ascendc.py {task_name}
```

**4.3 Save validation result:**

Parse verification output. Write to `{task_dir}/precision_tuning/validation_result_attempt_{attempt}.json`:

```json
{
  "attempt": <N>,
  "correctness_passed": true/false,
  "evaluate_stdout": "<verification output>",
  "match_rate": "<extracted percentage>",
  "max_diff": "<extracted max_diff>"
}
```

Extract rules:
- If verification prints "PASS" → `correctness_passed: true`, `match_rate: "100.0"`, `max_diff: "0.0"`
- If verification prints mismatch info → parse mismatch_ratio, max_abs_diff from output

**4.4 Gate validation + loop control:**
```bash
python3 skills/ascendc/ascendc-precision-tuner/scripts/precision_gate.py \
    --step validate --task-name {task_name} --workdir "{workdir}" --attempt {attempt}
```

| loop_signal | Meaning | Action |
|-------------|---------|--------|
| **PASS** | Precision passed | → Step 5 (success) |
| **CONTINUE** | Not passed but improving | → Archive, attempt+1, back to Step 1 |
| **STOP** | Not passed, not improving, or max attempts | → Step 6 (failure report) |

**Agent MUST obey loop_signal. Do not override.**

---

### Archive (CONTINUE)

```bash
mkdir -p "{task_dir}/precision_tuning/history/attempt_{attempt}"
cp "{task_dir}/precision_tuning/forensics_report_{attempt}.json" \
   "{task_dir}/precision_tuning/history/attempt_{attempt}/forensics_report.json"
cp "{task_dir}/precision_tuning/precision_audit_{attempt}.md" \
   "{task_dir}/precision_tuning/history/attempt_{attempt}/precision_audit.md"

# Update best code if improved
current_mr=$(python3 -c "import json; r=json.load(open('{task_dir}/precision_tuning/validation_result_attempt_{attempt}.json')); print(r.get('match_rate', '0'))")
best_mr=0
if [ -f "{task_dir}/precision_tuning/history/current_best/match_rate.txt" ]; then
    best_mr=$(cat "{task_dir}/precision_tuning/history/current_best/match_rate.txt")
fi
is_better=$(python3 -c "print('yes' if float('$current_mr') >= float('$best_mr') else 'no')")
if [ "$is_better" = "yes" ]; then
    mkdir -p "{task_dir}/precision_tuning/history/current_best/code_snapshot"
    cp "{task_dir}/kernel/"*.cpp \
       "{task_dir}/precision_tuning/history/current_best/code_snapshot/"
    echo "$current_mr" > "{task_dir}/precision_tuning/history/current_best/match_rate.txt"
    echo "Improved: $best_mr → $current_mr"
fi

# Save next attempt starting snapshot
next=$((attempt + 1))
mkdir -p "{task_dir}/precision_tuning/history/attempt_${next}/code_snapshot"
cp "{task_dir}/kernel/"*.cpp \
   "{task_dir}/precision_tuning/history/attempt_${next}/code_snapshot/"
```

Then `attempt += 1`, back to Step 1.

---

### Step 5: Success

```bash
mkdir -p "{task_dir}/precision_tuning/history/success/code_snapshot"
cp "{task_dir}/kernel/"*.cpp \
   "{task_dir}/precision_tuning/history/success/code_snapshot/"
echo "100.0" > "{task_dir}/precision_tuning/history/current_best/match_rate.txt"
```

Output:
```
[PRECISION_TUNING_RESULT]
  status: SUCCESS
  attempts: <total rounds>
  final_match_rate: 100.0
  root_cause_summary: <one sentence>
  fix_summary: <one sentence>
```

---

### Step 6: Failure Report

```
[PRECISION_TUNING_RESULT]
  status: FAILED
  attempts: <total rounds>
  loop_stop_reason: <Gate reason>
  history:
    attempt 0: hint=<pattern>, mismatch=<ratio>, fix=<summary>
    ...
  remaining_issue: <description>
  suggestion: <advice for manual analysis>
```

Best code is saved in `history/current_best/`. To restore:
```bash
cp "{task_dir}/precision_tuning/history/current_best/code_snapshot/"*.cpp \
   "{task_dir}/kernel/"
```

## Note

- Every Gate verification is mandatory
- loop_signal is determined by Gate script, Agent must obey
- Forensics data is the foundation of analysis — do not analyze without it
- Knowledge base entries are only written on success
- Compile failures do not count as tuning rounds (max 3 compile retries)
- Fix code directly in {task_dir}/kernel/*.cpp
